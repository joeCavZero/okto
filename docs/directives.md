# Directives

Directives describe assembly sections and data bytes. Unlike processors, they
remain in the parsed token stream and are interpreted by the assembler.

The main code section is `.code`. OKTO also recognizes data sections used by the
fantasy console interface.

| Section    | Type | Usage        |
|:----------:|:----:|:-------------|
| `.code`    | Code | Executable VM instructions. |
| `.color`   | Data | Console color memory.       |
| `.palette` | Data | Console palette memory.     |
| `.sprite`  | Data | Console sprite memory.      |
| `.audio`   | Data | Console audio memory.       |

---

## Code Sections

Executable instructions belong in `.code`.

```python
.code
START:
    li $a, 72
    li $c, OKTO_PRINT_CHAR
    call
```

If no section has been selected yet, the assembler starts as if it were reading
the `.code` section.

Labels in code sections resolve to instruction addresses. Since each native
instruction is one byte, a code label points to the byte offset of the
instruction it labels.

Pseudo-instructions are expanded before final code generation. You can read
more about that in the
[pseudo-instructions documentation](/docs/pseudo-instructions.md).

---

## Data Sections

Data sections contain bytes generated by data directives.

```python
.color
COLOR_BLACK:
    .byte 0, 0, 0, 255
```

Labels in data sections resolve to byte offsets inside that section.

## Data Directives

| Directive   | Syntax                 | Output                                      |
|:------------|:-----------------------|:--------------------------------------------|
| `.byte`     | `.byte n[, n...]`      | One byte per numeric literal.               |
| `.double`   | `.double n[, n...]`    | Two bytes per numeric literal, Big Endian.  |
| `.char`     | `.char 'c'`            | One byte containing the character value.    |
| `.string`   | `.string "text"`       | The string bytes.                           |
| `.stringz`  | `.stringz "text"`      | The string bytes followed by `0`.           |
| `.space`    | `.space n`             | `n` zero bytes.                             |
| `.checkpoint` | `.checkpoint`        | No bytes; labels before it mark the current offset. |

Numeric data for `.byte` must fit in 8 bits. Numeric data for `.double` and
`.space` must fit in 16 bits.

Examples:

```python
.palette
    .byte 255, 255, 255, 255
    .double 0x1234
    .char 'A'
    .string "OKTO"
    .stringz "done"
    .space 16
```

The `.double` directive stores the most significant byte first. For example,
`.double 0x1234` emits `0x12` followed by `0x34`.

## Literals

Numbers can be written in decimal, hexadecimal, or binary form:

```python
.byte 42
.byte 0x2A
.byte 0b0010_1010
```

Underscores may be used inside numeric literals for readability.

Strings use double quotes. Character literals use single quotes.

```python
.string "Hello"
.char 'H'
```

The assembler also accepts the `s"..."s` string form used by the lexer.

## Labels Before Data

One or more labels may appear before a data directive. They all point to the
current byte offset in the selected data section.

```python
.sprite
PLAYER:
PLAYER_IDLE:
    .byte 0b0001_1110
```

You can use a `.checkpoint` when you want a label to mark the current offset
without emitting bytes.

```python
.audio
INTRO_START:
    .checkpoint
```

Data sections and stack memory are described from the VM perspective in the
[memory documentation](/docs/memory.md). Processors such as `@include` and
`@macro` are described in the [processors documentation](/docs/processors.md).
